# L1 Input Processing (1) 知识点讲解

## 一、知识点讲解

<a id="kp-01"></a>
### 01. 数字图像是像素网格（Digital images as grids of pixels）

**直觉**：电脑里的图片不是一块"会发光的画布"，而是一张由无数小方格拼成的表格，每个小方格里填一个颜色数字。

**是什么**：像素（pixel = picture element，图像元素）是图像的最小组成单元，同时携带两类信息：颜色（colors）和空间位置（spatial locations）。灰度图（grayscale image）的每个像素只存一个亮度值；彩色像素通常存三个通道值（channel values，即 R、G、B 各一个）。所以一张图在计算机里本质上是一个"结构化数组"（structured array），而不是不可分割的物体。

**为什么**：神经网络（neural network）只会对数字做数值运算，它不会"看"图。把图像拆成"带坐标的颜色数字网格"，是把人类看到的画面翻译成机器能计算的输入的第一步。

**怎么用**：课件里的 3×3 网格中，每个格子写一个数字——灰度图一个格子一个数；彩色图一个格子三个数（R/G/B）。位置由格子的行列坐标决定，颜色由格子里的数值决定。

**类比**：像一张 Excel 表格：行、列是位置，格子里填的数值是颜色。改格子里的数，图就变了；格子越多，图越精细。

**易错点**：像素不只是"颜色"，还包含位置信息；同一个颜色值出现在不同位置，是不同像素。

**前置**：无。

<a id="kp-02"></a>
### 02. RGB 颜色模型（RGB color model）

**直觉**：彩色显示器靠红、绿、蓝三盏"灯"按不同亮度叠加，混合出几乎所有颜色。

**是什么**：RGB 是加色模型（additive color model），每个像素记一个三元组 (R, G, B)，分别代表红、绿、蓝三个通道的强度，通常取 0–255 的整数。三通道全满 (255, 255, 255) 是白色；全零 (0, 0, 0) 是黑色；只有红满 (255, 0, 0) 是纯红；红多绿中蓝无 (255, 220, 0) 得到黄色。

**为什么**：人眼视网膜上有大致对应红、绿、蓝三种波段的感光细胞，用这三种颜色可以合成绝大多数可见颜色；同时屏幕硬件也按三色子像素制造，因此三通道成为图像存储的通用标准。

**怎么用**：常用颜色对照——红 (255, 0, 0)、绿 (0, 255, 0)、蓝 (0, 0, 255)、白 (255, 255, 255)、黄 (255, 220, 0)、黑 (0, 0, 0)。数值越大，该通道越"亮"、贡献越强。

**类比**：像调颜料：三管颜料（红、绿、蓝）各挤多少，混合出最终颜色；(255, 220, 0) 就是"红多、绿中、蓝无"，得到黄色。

**易错点**：RGB 三个值不是"颜色名称"，只是三个通道的强度；0–255 是 8 位整数的常见约定，也可归一化到 0–1（见 kp-09）。

**前置**：承接 kp-01。

<a id="kp-03"></a>
### 03. 图像形状 H×W×C（Image shape H × W × C）

**直觉**：描述一张图的"尺寸规格"要用三个数：多高、多宽、几个颜色通道。

**是什么**：一张 RGB 图可写作张量 I ∈ ℝ^{H×W×3}，其中 H 是图像高度（height，行数）、W 是宽度（width，列数）、C 是通道数（channels），RGB 图通常 C = 3。直观上就是 3 张同样大小的矩阵叠在一起（3 stacked matrices）。

**为什么**：三维张量是图像在计算里的标准容器：前两维编码空间位置，第三维编码颜色。后续所有操作（裁剪、归一化、分块、投影）都建立在这个形状约定上。

**怎么用**：224×224 的 RGB 图 = 224 行 × 224 列 × 3 通道 = 224×224×3 = 150,528 个数。

**类比**：把一张图想成三张透明胶片（红、绿、蓝各一张）叠在一起，每张胶片是一个 H×W 的数字矩阵。

**易错点**：C 不一定等于 3——多光谱图像（multispectral images，如含红外波段的卫星图）可以有更多通道，此时 C 大于 3。

**前置**：见 kp-01、kp-02。

<a id="kp-04"></a>
### 04. 维度顺序与批量维（Dimension order: HWC / CHW / BCHW）

**直觉**：同样三个数（H、W、C），谁在前谁在后决定了程序怎么读这张图；读错顺序是新手最常见的 bug。

**是什么**：图像文件与 NumPy 通常用 H×W×C（如 224×224×3，通道在最后）；PyTorch 张量用 C×H×W（如 3×224×224，通道在最前）；一次喂一批数据时再加一个批量维 B，得到 B×C×H×W（如 32×3×224×224，32 是这批图片的张数）。

**为什么**：不同库对内存布局（哪个维度在内存里连续存放）有不同约定，深度学习框架为了计算效率把通道放到最前。维度顺序只是"记账方式"，数据本身没变——但模型接口只认其中一种，顺序错了数值就错位。

**怎么用**：读到一张 HWC 的图，进 PyTorch 前要转成 CHW；一次推理多张图则堆成 BCHW。转换只重排维度，不改数值。

**类比**：像日期写法：同一个日期可以写成 2026-09-01（年-月-日）或 01-09-2026（日-月-年），数字一样，约定不同，填表填错位就出错。

**易错点**：数值都对、维度顺序错，模型输出全乱——课件专门点出这是常见 bug（common bug）。

**前置**：见 kp-03。

<a id="kp-05"></a>
### 05. 分辨率与计算成本（Resolution and cost）

**直觉**：图越清晰（分辨率越高），细节越多，但要算的东西也越多。

**是什么**：分辨率由 H×W 决定。224×224 有 50,176 个像素；长宽各放大 2 倍到 448×448，像素变成 200,704，是原来的 4 倍——因为面积随边长平方增长（2×2 = 4）。

**为什么**：高分辨率能保住小物体和文字细节，但像素数增长会同时推高内存占用、视觉 token 数和计算量，所以输入分辨率是一个设计权衡（design trade-off）。

**怎么用**：像素数 = H × W。224×224 = 50,176；448×448 = 200,704。

**类比**：把照片放大冲印，尺寸翻倍，纸张面积和打印成本大约是原来的 4 倍。

**易错点**："长宽各 2 倍"不是"计算量 2 倍"，而是约 4 倍（像素按面积算）。

**前置**：见 kp-03；视觉 token 侧的代价见 kp-24。

<a id="kp-06"></a>
### 06. 图像文件与图像张量（Image file vs image tensor）

**直觉**：硬盘上的 .jpg 和模型要的张量不是一回事，中间要"解码"。

**是什么**：JPEG/PNG 文件里存的是压缩信息和文件元数据（metadata），不是直接可用的像素数组；解码算法（decode）把它们重建成像素值。重建后再转成灰度或 RGB 格式，并检查形状（shape）、通道顺序（channel order）、数据类型（data type）、数值范围（value range）。

**为什么**：文件格式是为省存储空间设计的压缩表示；模型需要的是规范化的数值张量。跳过或做错解码，模型看到的全是垃圾数。

**怎么用**：流程是 JPEG/PNG → 解码 → RGB 像素 → 张量。调试时重点检查四点：形状对不对、通道顺序对不对、数据类型对不对（如 uint8 还是 float32）、数值范围对不对（0–255 还是 0–1）。

**类比**：像 .zip 压缩包：里面装的是数据，但要先解压才能用；文件头还带各种说明信息（元数据）。

**易错点**：把"文件字节"直接当"像素数值"喂给模型，是最典型的预处理错误之一。

**前置**：见 kp-04。

<a id="kp-07"></a>
### 07. 图像预处理流水线（Image preprocessing pipeline）

**直觉**：模型有个固定接口，进模型前要把五花八门的照片都"加工成统一规格"。

**是什么**：典型流水线为：解码（Decode）→ RGB → 调整尺寸（Resize）→ 裁剪/填充（Crop/Pad）→ 重缩放（Rescale）→ 归一化（Normalize）。处理器（processor）把各种真实图像改造成模型要求的固定格式。

**为什么**：模型是在训练时见过的某一形状和数值分布上学出来的；推理（inference）时的预处理必须与预训练（pretraining）时一致，否则输入分布漂移、模型表现变差。课件强调：推理流水线要匹配预训练时用的预处理。

**怎么用**：对任何一张新图，走完这五步再进模型；最实用规则——直接用预训练模型官方发布的 processor，别自己另写一套。

**类比**：像体检前的样本统一处理：血样要离心、标定、按同样条件存放，检测机器才能横向比较。

**易错点**：预处理改变的是"什么信息能到达模型"；步骤顺序或参数错了，后面全错。

**前置**：见 kp-06。

<a id="kp-08"></a>
### 08. 调整尺寸、裁剪与填充（Resize, crop, padding）

**直觉**：让不同大小、不同长宽比的图片统一规格，同时还能"变出更多训练样本"。

**是什么**：三种空间操作——Resize（调整尺寸）改变空间尺寸，可能扭曲长宽比；Crop（裁剪）保留选中区域，可能切掉边缘物体；Padding（填充）在四周加边，保留完整内容。它们属于数据增强（data augmentation）。

**为什么**：数据增强有两个作用——降低过拟合（reduce overfitting）和增加数据多样性（increase data diversity）。过拟合指模型死记训练样本、遇到新图就失灵；多角度、多裁剪的样本让模型学到更本质的特征。

**怎么用**：把不同尺寸图片 resize 到统一的 224×224；训练时随机 crop 一块、随机翻转，相当于把一张图变成多张"新图"。

**类比**：像摄影师从同一场景拍不同取景和角度，得到的照片各不相同，但都能用来训练"这是什么场景"。

**易错点**：推理时过度裁剪可能切掉关键物体（见 kp-12 的 wrong crop）。

**前置**：见 kp-07。

<a id="kp-09"></a>
### 09. 像素重缩放（Pixel rescaling to [0,1] and [-1,1]）

**直觉**：把 0–255 的大整数压成 0–1（或 -1–1）的小数，数字变好算，图的意思没变。

**是什么**：重缩放只改数值尺度、不改图像含义。到 [0,1]：x' = x / 255。到 [-1,1]：先做 x = x − 255/2（减去中点），再做 x' = x / (255/2)（除以半幅）。对应关系：0 → 0.000，64 → 0.251，128 → 0.502，192 → 0.753，255 → 1.000。

**为什么**：0–255 是大整数，直接进网络容易让梯度、权重等数值不稳定；压到 0 附近的小区间让数值量级统一、计算更稳。

**怎么用**：分步执行——原始值除以 255 得到 [0,1]；若还要 [-1,1]，就"减中点、除半幅"。

**类比**：把摄氏温度换算成 0 到 1 的"舒适度"，数值变了，冷暖信息不变。

**易错点**：重缩放是线性缩放，不改变各通道间的相对关系；它和归一化（kp-10）不同，这里不涉及均值和标准差。

**前置**：见 kp-07。

<a id="kp-10"></a>
### 10. 均值–标准差归一化（Mean–std normalization）

**直觉**：先"减平均"让数据中心对齐，再"除波动"让数值尺度统一——相当于把数据"摆正"。

**是什么**：公式 x' = (x − μ) / σ。减均值 μ（subtract μ）让数据中心移到 0（center the data around the mean）；除以标准差 σ（divide by σ）让数值表达相对波动（express values relative to variation）。RGB 三个通道通常各用各的 μ 和 σ。输出可能出现负值或大于 1，这都正常。

**为什么**：不同通道的亮度分布差别大（比如红色整体偏亮、蓝色整体偏暗），分别按各自统计量归一化后，三通道量级可比，网络训练更稳（见 kp-11）。

**怎么用**：简单例子 x = 0.80, μ = 0.50, σ = 0.25，则 x' = (0.80 − 0.50) / 0.25 = 1.20。完整例子：原始像素 (128, 64, 255)，先除以 255 得 (0.502, 0.251, 1.000)，再减 μ = 0.5、除 σ = 0.25，得 (0.008, −0.996, 2.000)——逐通道独立处理。

**类比**：像考试成绩标准化：每人分数减去平均分、再除以标准差，就知道你比平均高几个"波动单位"。

**易错点**：μ 和 σ 必须用预训练模型官方给定的值，不能用自己这批图现算的统计量；输出超出 [0,1] 是正常的。

**前置**：见 kp-09。

<a id="kp-11"></a>
### 11. 输入归一化与批/层归一化（Input vs batch vs layer normalization）

**直觉**：同样是"归一化"，有的发生在进模型前，有的发生在模型内部，位置和作用对象不同。

**是什么**：三种归一化——输入归一化（input normalization）在模型之前，作用对象是像素（pixels）；批归一化（batch normalization）在网络内部，作用对象是一批特征（batch features）；层归一化（layer normalization）在 Transformer 内部，作用对象是单个样本的 token 特征（token features）。

**为什么**：归一化总体解决"数值尺度不稳"的问题。课件给出四个动机：稳定尺度（避免不必要的过大输入值）、让通道可比（减小通道间统计差异）、匹配预训练（让推理输入落在预期分布内）、统一数据尺度（不同数据源用同一尺度）。

**怎么用**：最实用规则——用预训练模型自带的 processor 做输入归一化，μ、σ 都按官方值；批/层归一化是网络结构的一部分，由模型自己学、自己算。

**类比**：像"进考场前统一安检"（输入归一化）和"考场内按小组或按个人调整状态"（批/层归一化），位置不同、对象不同。

**易错点**：别把三者混为一谈；输入归一化用的是训练集的统计量，而批/层归一化在推理时用的是训练时累积的统计量或按样本现算。

**前置**：见 kp-07、kp-10。

<a id="kp-12"></a>
### 12. 常见图像输入错误（Common image input failures）

**直觉**：很多"模型表现差"，其实在进模型之前就已经错了。

**是什么**：五类典型错误——RGB↔BGR（红蓝通道顺序颠倒）、wrong range（0–255 没归一化直接用）、wrong crop（裁剪切掉了关键物体）、low resolution（分辨率太低，小物体认不出）、wrong shape（HWC/CHW 维度顺序错）。

**为什么**：模型是哑的——它只会按约定读数字，输入规格错了就"理解错"。课件总结：模型错误可能始于模型之前（A model error may begin before the model itself）。

**怎么用**：喂图前自查清单——通道顺序对不对、数值范围对不对、关键物体在不在裁剪区、分辨率够不够、shape 对不对。

**类比**：像寄快递填错收件人地址——包裹内容没问题，但送错地方等于白寄。

**易错点**：OpenCV 默认读成 BGR，PyTorch 等常要 RGB，两套库混用时最容易踩这个坑。

**前置**：见 kp-04、kp-07、kp-09。

<a id="kp-13"></a>
### 13. 文本处理流水线（Text processing pipeline）

**直觉**：模型同样不"读"句子，它要先把你写的话切成编号，再变成向量。

**是什么**：流水线：原始句子（raw sentence）→ 分词器（tokenizer）→ 词元（tokens）→ 词元编号（token IDs）。例："A student is reading a book." → [A] [student] [is] [read] [ing] [a] [book] [.]。词元可以是词、子词、字符、标点或特殊符号。

**为什么**：神经网络只处理数字，文本必须先离散化、再向量化。注意：分词（tokenization）和嵌入（embedding）是两个不同的步骤——前者产编号，后者产向量。

**怎么用**：一句话进分词器，输出一串 token 序列，再查词表得到 ID 序列，再查嵌入矩阵得到向量序列（后两步见 kp-15、kp-16）。

**类比**：像给图书馆的书编号：先拆成"册"（token），每册给个编号（ID），编号再对应书架上的实体（向量）。

**易错点**：分词和嵌入不是一回事；"reading" 可能被拆成 read + ing 两个 token，取决于分词器。

**前置**：无（Part III 的起点）。

<a id="kp-14"></a>
### 14. 分词与子词（Tokenization and subwords）

**直觉**：把词整块切太大、按字母切太碎，子词切法取中间，是现在的折中方案。

**是什么**：三种粒度——整词（whole words）：词表巨大，遇到新名字、新词不认识；字符（characters）：一个词变成很长的 token 序列，单个字符语义弱；子词（subwords）：可复用的片段，平衡词表大小与序列长度/语义。例：playing → play + ing。

**为什么**：整词法遇到没见过的名字或新词直接失败；字符法序列太长、语义太弱；子词把常见词根和词缀拆开复用，既控制词表规模，又能组合出没见过的词。

**怎么用**：分词器把 "playing" 切成 "play" 和 "ing" 两个子词 token，两者都能在词表里查到、可复用。

**类比**：像中文把"学生们"拆成"学生"+"们"——"学生"可以复用到很多词里。

**易错点**：同一句话用不同分词器会切出不同 token，导致 ID 完全不同；换模型就要换对应的分词器。

**前置**：见 kp-13。

<a id="kp-15"></a>
### 15. 词表与 Token ID（Vocabulary and token IDs）

**直觉**：token ID 只是词表里的"地址/编号"，数字大小不代表含义。

**是什么**：每个 token 在预定义词表（vocabulary）里对应一个整数 ID。例：<bos> → 1，A → 37，student → 526，reading → 1042，book → 928。ID 是词表中的地址，不含语义大小关系（not semantic significance）。

**为什么**：把离散符号变成整数，是后续"查表取向量"（kp-16）的前置步骤；编号固定、可索引，便于高效查找。

**怎么用**：句子 → token 序列 → ID 序列（如 [37, 526, 1042, 928]）→ 下一步查嵌入矩阵。

**类比**：像学生学号：学号只是索引，学号大不代表成绩好或年龄大。

**易错点**：ID 数字没有"大小即语义"的含义——526 并不比 37 "更高级"。

**前置**：见 kp-13、kp-14。

<a id="kp-16"></a>
### 16. 词嵌入：从 ID 查矩阵（Token embedding lookup）

**直觉**：每个词在"语义地图"上有一个坐标，嵌入矩阵就是这张地图，查表就能拿到坐标向量。

**是什么**：维护一个嵌入矩阵 E ∈ ℝ^{V×D}，V 是词表大小（vocabulary size），D 是嵌入维度（embedding dimension）。用 token ID 做行号去 E 里取一行，就得到该 token 的向量。例：ID 526（student）→ e₅₂₆ = [0.21, −0.47, 0.83, …]。嵌入值是训练时从数据中学出来的（learned from data）。

**为什么**：模型要的是向量而不是整数。查表把离散的 ID 变成连续空间里的点，每个词得到一个低维、稠密、可学习的表示，便于后续神经网络运算。

**怎么用**：一步查表——token ID 526 → 取 E 的第 526 行 → 得到 D 维向量。整句话就是把每个 ID 换成一行向量，得到向量序列。

**类比**：像查字典：ID 是页码，翻到那一页（那一行）拿到完整释义（向量）。

**易错点**：嵌入矩阵的每一行是"可学习的参数"，初始是随机的，训练后才有语义；D（嵌入维度）是超参数，常见几十到上千。

**前置**：见 kp-15。

<a id="kp-17"></a>
### 17. one-hot 与稠密嵌入（One-hot vs dense embedding）

**直觉**：one-hot 是"只亮一盏灯的开关"，稠密嵌入是"每个词一个坐标点"，后者信息密度高得多。

**是什么**：one-hot 向量形如 [0, 1, 0, 0, 0, 0, …]，长度等于词表大小，只有一个位置是 1。缺点：表示能力小、维度极高、稀疏离散、没有自然的语义相似性（任意两个不同词的余弦相似度都是 0）。稠密嵌入（dense embedding）形如 [0.70, −0.20, 0.40, …]，维度低（≥2）、连续、训练中学得，能表达词与词之间有意义的关系。

**为什么**：one-hot 把每个词当孤立符号，任何两个词"距离"都一样，学不到"猫和狗相近"；稠密嵌入把离散符号变成连续特征空间里的点，相似词在空间里可以靠近。

**怎么用**：把 one-hot 与 E 相乘（或直接查表）就得到稠密向量；实际实现直接用查表（kp-16），one-hot 是理解上的中间形式。

**类比**：one-hot 像给每个人发一把互不相同的钥匙，钥匙之间没有"远近"；稠密嵌入像把人放到地图上，同城的人坐标相近。

**易错点**：one-hot 里"1 的位置"本身没语义，向量的语义全靠嵌入矩阵学出来；余弦相似度为零只是 one-hot 的数学结果。

**前置**：见 kp-16。

<a id="kp-18"></a>
### 18. 嵌入空间的语义相似性（Semantic similarity in embedding space）

**直觉**：训练好的嵌入像一张"词语地图"，意思相近的词会住在附近。

**是什么**：训练后，相关词在嵌入空间中距离近——cat、dog、tiger 一类，car、bus 一类，book 单独一类。相似性是从数据中学出来的（learned from data），不是人手工设定的。

**为什么**：如果"猫"和"狗"的向量相近，模型做下游任务时就能利用这种相似性（比如把对"猫"的知识泛化到"狗"），这正是稠密嵌入优于 one-hot 的核心价值。

**怎么用**：用余弦相似度（cosine similarity）或欧氏距离衡量两个向量的接近程度；相似词对得分高，无关词对得分低。

**类比**：像城市地图：宠物店、动物医院在"动物区"扎堆，修车厂、加油站扎在"汽车区"。

**易错点**：相似性是"分布相似"（出现在相似上下文的词会靠近），不等于同义词；不同语料学出的空间不同，相似性也不同。

**前置**：见 kp-17。

<a id="kp-19"></a>
### 19. 位置嵌入与注意力掩码（Position embedding and attention mask）

**直觉**：词序很重要（"狗咬人" ≠ "人咬狗"），所以要给每个词加"位置信息"，还要屏蔽掉填充出来的空位。

**是什么**：token 嵌入本身不含顺序，需加上位置信息（position information）得到"有序序列"。例："Dog bites man." 与 "Man bites dog." 词相同但顺序不同、含义相反。对于变长句子，会用 <pad> 填充对齐，并配一个注意力掩码（attention mask）——如 "A cat sleeps . <pad> <pad>" 对应 [1, 1, 1, 1, 0, 0]，0 表示该位置是填充、不是真实内容。

**为什么**：自注意力（kp-20）本身不关心顺序，必须显式注入位置；批量处理要求句子等长，填充位又不能参与计算，所以要用掩码挡住。

**怎么用**：token 向量 = 词嵌入 + 位置嵌入；把 <pad> 位置在掩码里标 0，让模型在注意力计算时忽略这些位置。

**类比**：像排队点名：顺序即身份；空椅子（pad）要用"请忽略"标签挡住，别把空椅子当真人。

**易错点**：掩码为 0 的位置必须真正被忽略，否则填充符号会被当成内容参与计算。

**前置**：见 kp-16；为 kp-20 铺垫。

<a id="kp-20"></a>
### 20. 自注意力的上下文交互（Contextual interaction via self-attention）

**直觉**：同一个词在不同句子里意思不同（bank 可以是"银行"或"河岸"），自注意力让每个词"看看周围邻居"再决定自己是谁。

**是什么**：初始 token 嵌入主要只取决于 token ID；自注意力（self-attention）让 token 之间信息流动（facilitates token information flowing），经过它之后，每个词的表示会带上周围词的信息。因此同一个 token 在不同句子中可以表达不同含义。

**为什么**：一词多义（polysemy）单靠查表解决不了——"bank" 在 "bank account"（银行账户）和 "river bank"（河岸）里是同一个 ID、同一个初始向量，只有结合上下文才能消歧。

**怎么用**：token 向量序列进入 Transformer 的自注意力层，每个 token 与序列中其他 token 交互、加权聚合信息，输出"带上下文"的新表示。

**类比**：像聚会上的自我介绍：单独听"银行"不知何意，听到前后文"账户"或"河"就明白了——信息来自周围人。

**易错点**：初始嵌入和"经过自注意力后的表示"不是一回事；同一个 token 的向量会随句子不同而不同。

**前置**：见 kp-16、kp-19。

<a id="kp-21"></a>
### 21. 图像分块与线性投影（Image patches → visual tokens）

**直觉**：文字能切成词，图片也能切成小方块，每个方块"压"成一个向量，就当"视觉词元"用。

**是什么**：把图像切成若干 patch（分块），每个 patch 展平（flatten）成一长条，再过一个线性投影（linear projection），得到一个向量，即视觉 token（visual token）。一个 patch 不一定是物体或词，其含义由上下文赋予。

**为什么**：语言模型只会处理"一串向量"，要把图像塞进同一个序列，就得把图离散化成一组向量，与文本 token 同构，才能一起处理。

**怎么用**：例：224×224 图按 16×16 的 patch 切，得 14×14 = 196 个 patch，每个展平为 16×16×3 = 768 维向量，再线性投影到目标维度（如 4096），得 196 个视觉 token。

**类比**：像把一张大拼图拆成小方块，每块贴个编号（向量）登记，整体信息仍保留在"哪块挨着哪块"上。

**易错点**：patch 不等于"物体"或"单词"，它是固定网格切出来的矩形块，可能横跨多个物体。

**前置**：见 kp-04、kp-13（与文本 token 的对应关系）。

<a id="kp-22"></a>
### 22. 视觉编码器与投影器（Vision encoder and projector）

**直觉**：图像先经过"视觉专用翻译官"，再经过"尺寸对齐器"，才能和文本向量并肩作战。

**是什么**：归一化图像 → 视觉编码器（Vision Encoder）提取视觉模式与语义 → 视觉特征 → 投影器（Projector）把特征维度调整到语言模型的尺寸 → LLM 尺寸的 token。形状例：[1, 3, 224, 224] → [1, 196, 768] → [1, 196, 4096]。

**为什么**：视觉编码器擅长从像素提取高层特征，但它的输出维度（如 768）往往和大语言模型的嵌入维度（如 4096）不一致；投影器做一次线性映射对齐维度，让两类 token 能在同一序列里拼接。

**怎么用**：批量 B=1 时——图像张量 [1, 3, 224, 224]（B, C, H, W）→ 编码器输出 [1, 196, 768]（B, N, D1，N 是视觉 token 数）→ 投影器输出 [1, 196, 4096]（B, N, D2）。

**类比**：像两个国家的代表开会，先由本国翻译把话翻好（编码器），再统一转换成会议通用语言（投影器），大家才能坐一桌。

**易错点**：编码器输出的 768 和投影后的 4096 含义不同——前者是视觉特征维度，后者是"对齐到 LLM"后的 token 维度。

**前置**：见 kp-21。

<a id="kp-23"></a>
### 23. 多模态输入流水线（Complete multimodal input pipeline）

**直觉**：把视觉 token 和文本 token 拼成"一条长队"，一起交给多模态模型。

**是什么**：视觉 token + 文本 token → 一条多模态序列。形状变化例：图像张量 [1, 3, 224, 224]（B, C, H, W）→ 视觉输出 [1, 196, 768]（B, N, D1）→ 投影后 [1, 196, 4096]（B, N, D2）；12 个文本 token 为 [1, 12, 4096]（B, n, D2）；拼接成 [1, 208, 4096]（B, N+n, D2），即 196 + 12 = 208 个 token。

**为什么**：多模态大语言模型（MLLM）用同一个 Transformer 处理视觉和文本向量，前提是二者维度一致、能拼成一个共享序列——这就是"从原始像素和文字到多模态 token"的完整路径。

**怎么用**：分别把图走视觉分支、文本走文本分支，得到同维度（D2）向量后，沿 token 数维度拼起来（196 + 12 = 208），送入统一模型。

**类比**：像一列混合编队的火车：前面 196 节"图像车厢"、后面 12 节"文字车厢"，但每节车厢规格（4096 维）统一，可以一起开。

**易错点**：拼接必须在"特征维度一致"的前提下沿 token 数维度做；D2 不一致无法拼接。

**前置**：见 kp-22、kp-16。

<a id="kp-24"></a>
### 24. 分辨率与视觉 token 数量（Resolution vs number of visual tokens）

**直觉**：图越大，切出来的视觉 token 越多——细节更全，但计算更贵。

**是什么**：固定 patch 大小下，224×224 → 14×14 个 patch = 196 个视觉 token；448×448 → 28×28 个 patch = 784 个视觉 token（是 4 倍）。token 越多，能保留的小文字、小物体细节越多，但计算量也越大。

**为什么**：视觉 token 数直接决定多模态序列长度（kp-23 里的 N），而 Transformer 的计算量随序列长度快速增长，所以"清晰"与"快速"要权衡。

**怎么用**：需要读小字、数小物体时提高分辨率；只做粗分类时用低分辨率省算力。

**类比**：像切照片拼图：同样大小的拼块，照片越大块数越多，拼起来越费劲但细节越全。

**易错点**：token 数随边长平方增长——448 是 224 的两倍边长，token 却是 4 倍，不是 2 倍。

**前置**：见 kp-21、kp-23；呼应 kp-05。

<a id="kp-25"></a>
### 25. 好的多模态输入（Good multimodal input）

**直觉**：想让模型答得好，既要给清晰的图，也要给问得清楚的问题。

**是什么**：好输入 = 清晰图像 + 详细提示（prompt）。弱提示："Describe it."（描述它）；强提示："Identify the three main objects. For each, state position and visible color. Do not infer information not shown."（识别三个主要物体，逐个说明位置和可见颜色，不要推断图中没显示的信息）。三条要点：用合适的图像分辨率；避免会去掉关键证据的数据增强；把问题和输出结构写得具体。

**为什么**：模型只按你给的输入作答，图和问题含糊，答案就含糊；明确"要什么、什么格式、不要什么"能大幅提升输出质量。

**怎么用**：描述任务时给三要素——对象、属性、约束（如"不要推断未显示信息"）；确保图像里关键细节清晰可见。

**类比**：像向人问路：说清"找哪家店、从哪条街、只要步行路线"，比一句"怎么走"有用得多。

**易错点**：别在预处理时把证据切掉（如把车牌裁没），也别让模型脑补图中不存在的内容。

**前置**：见 kp-23、kp-12。

## 二、知识点联系

- kp-01 → kp-02（依赖）：像素是承载 RGB 三值的载体，先有"像素 = 带坐标的颜色"，才有三通道的 (R, G, B)。
- kp-02 → kp-03（依赖）：RGB 的三通道直接构成 H×W×C 里的 C = 3。
- kp-03 → kp-04（应用）：H×W×C 是 HWC 记法，调换顺序得到 CHW，加批量得到 BCHW。
- kp-04 → kp-06（应用）：解码后要检查 shape 和 channel order，正是维度顺序约定的落地。
- kp-03 → kp-05（应用）：分辨率就是 H×W，像素数随边长平方增长。
- kp-05 → kp-24（呼应）：图像分辨率最终体现为视觉 token 数量的增长。
- kp-06 → kp-07（依赖）：解码得到 RGB 像素，是预处理流水线的第一步。
- kp-07 → kp-08（依赖）：resize/crop/pad 是流水线中的空间处理环节。
- kp-07 → kp-09（依赖）：rescale 是流水线中的数值尺度环节。
- kp-09 → kp-10（依赖）：先 rescale 到 [0,1]，再做均值–标准差归一化。
- kp-10 → kp-11（应用）：输入归一化正是用 μ、σ 的 z-score，是三种归一化之一。
- kp-07/08/09 → kp-12（应用）：五类输入错误都源于预处理环节做错。
- kp-13 → kp-14（依赖）：分词是文本流水线第二步，子词是分词粒度的选择。
- kp-14 → kp-15（应用）：子词切分后，每个 token 去词表取 ID。
- kp-15 → kp-16（依赖）：ID 是嵌入矩阵的行号，查表取向量。
- kp-16 → kp-17（应用）：one-hot 是查表的等价视角，稠密嵌入是查表结果。
- kp-17 → kp-18（应用）：稠密嵌入使语义相似性成为可能。
- kp-16 → kp-19（依赖）：位置嵌入加在词嵌入上，需要先有词嵌入。
- kp-19 → kp-20（依赖）：注意力掩码和位置信息是自注意力正确工作的前提。
- kp-16/20 → kp-23（应用）：文本 token 进入多模态序列。
- kp-21 → kp-22（依赖）：patch 展平 + 线性投影产出视觉 token，编码器/投影器进一步处理。
- kp-22 → kp-23（依赖）：投影后的视觉 token 与文本 token 拼接成多模态序列。
- kp-21 → kp-24（应用）：视觉 token 数由 patch 网格决定，随分辨率增长。
- kp-23 → kp-25（应用）：理解完整流水线后，才能设计"好输入"。
